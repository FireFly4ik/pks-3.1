# КР3. Регистратура клиники

## Запуск

Из корня репозитория запустите Docker Desktop. Нужны Docker Compose и OpenSSL. Если база КР1 уже существует, используйте её прежний файл `.env` и тот же каталог проекта. Для первого запуска на пустой машине скопируйте `.env.example` в `.env` и задайте собственный `DB_PASSWORD`.

Один раз создайте локальный файл с ключом подписи и временным паролем администратора.

```sh
sh scripts/init-web-env.sh
```

Соберите и запустите оба контейнера.

```sh
docker compose --env-file .env --env-file .env.kr3 -f docker-compose.yml -f compose.web.yml up -d --build --wait
```

Откройте [регистратуру](http://localhost:8080/). Введите `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` из `.env.kr3`, затем задайте постоянный пароль. Создание первого администратора выполняется при пустой таблице сотрудников. После входа администратору доступны [Swagger UI](http://localhost:8080/swagger-ui.html) и [OpenAPI JSON](http://localhost:8080/v3/api-docs). Состояние приложения доступно по [адресу health](http://localhost:8080/actuator/health).

Чтобы остановить контейнеры с сохранением данных, выполните ту же команду Compose с `down` вместо `up -d --build --wait`.

## Как связаны три работы

Flyway создаёт схему КР1 при первом запуске и расширяет существующие таблицы `doctors` и `appointments`. Старые записи получают внешний код вида `VISIT-42` и UUID. JavaFX продолжает обращаться к числовым ключам через JDBC. Оба клиента работают с одним расписанием и общими ограничениями занятости пациента и врача. Архив служит для списка сотрудников. Освобождение времени происходит при отмене приёма.

На странице входа пациент может выбрать «Зарегистрироваться». Система создаёт веб-аккаунт и связанный профиль в общей базе, открывает личный кабинет и показывает свободное время выбранного врача. В «Моих записях» пациент видит только собственные приёмы. Сотрудники входят по email и работают с общим реестром в пределах своих ролей.

| Роль сотрудника | Возможности |
| --- | --- |
| Наблюдатель | Просмотр приёмов, поиск, фильтрация, справочник и аналитика |
| Регистратор | Также ведёт карточки, заметки, архив, массовые изменения и CSV |
| Администратор | Также управляет врачами, учётными записями и просматривает аудит |

## Сценарий защиты

1. Войдите под администратором. Создайте сотрудника с ролью регистратора и временным паролем. При первом входе сотрудник задаёт собственный пароль.
2. Создайте запись для существующего пациента. Укажите уникальный код, причину обращения, врача и свободное время по Москве. Запись открыта на 90 дней, в будни с 09:00 до 16:30 с шагом 30 минут.
3. Задайте готовность 50 и включите обратный звонок. Сервер выставит критический организационный приоритет. Это приоритет работы регистратора с записью. Для завершённых и отменённых приёмов он снимается.
4. Найдите карточку по фамилии врача, коду записи или запросу `готовность<60 звонок:да`. Измените сортировку, добавьте закреплённую заметку, выделите несколько записей и добавьте им тег.
5. Экспортируйте выборку в CSV. Для повторного импорта выберите обновление по внешнему коду, нажмите «Проверить», затем «Применить». Для новой строки укажите существующие логин пациента и код врача, новый внешний код и свободное время.
6. Переместите карточку в архив. Найдите её по фильтру `архив:все` и восстановите. Безвозвратное удаление доступно администратору при `PERMANENT_DELETE_ENABLED=true` в конфигурации Compose.
7. Откройте аналитику и журнал аудита. В Swagger доступны схемы запросов, поиск с пагинацией и операции по UUID. При редактировании передавайте `version` из последнего ответа. При конфликте сервер вернёт HTTP 409.

## Разработка

В IDEA откройте `backend/pom.xml` как Maven-проект и выберите JDK 21. Из корня репозитория тесты backend запускаются командой `./mvnw -f backend/pom.xml test`. Контроллеры и DTO находятся в `backend/src/main/java/ru/mirea/hospital/web`, SQL в `backend/src/main/resources/db/migration`, HTML, CSS и JavaScript в `backend/src/main/resources/static`. Клиент раздаётся самим Spring Boot. Для публичного контракта Android используйте `/api` и вход с `clientType=NATIVE`.
