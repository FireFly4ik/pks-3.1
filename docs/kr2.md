# КР2 — настольная система записи пациентов

## Запуск Hospital

Требуются JDK 21, запущенный Docker и графическая сессия. Команды выполняются из корня репозитория.

```bash
# Только при первом развёртывании: скопировать .env.example в .env и задать пароль.
docker compose up -d --wait
./mvnw javafx:run
```

На Windows: `mvnw.cmd javafx:run`. Настройки JDBC читаются из `.env`, переменные окружения имеют приоритет. Пароль не включается в JAR. Используется база `hospital` из КР1 на порту `55432`; сервер Spring для Hospital не нужен.

Если база пустая, можно зарегистрировать пациента в окне входа. Справочник врачей создаётся скриптом `schema.sql`. Для демонстрационных пользователей и записей **на пустой базе**:

```bash
./mvnw clean package
# В bash/zsh загрузить собственный .env в окружение для команды КР1:
set -a
source .env
set +a
java -jar target/java-hospital-1.0.0.jar --seed
```

Демо-вход: `admin` или `patient1`–`patient4`, пароль `DemoPass123!`. Инициализация отказывается менять непустую базу. Обычный запуск JAR открывает JavaFX; `--cli` оставлен для КР1. JAR с JavaFX содержит нативные библиотеки текущей ОС: на другом компьютере предпочтительно выполнить Maven-сборку заново.

## Реализация требований

| Требование | Реализация |
|---|---|
| Вход и регистрация | `login.fxml`, `LoginController`, проверки `UserService` |
| TableView / ObservableList | `main.fxml`, `MainController`; строки пациента ограничены сервисом |
| Создание | `appointment.fxml`: специальность → дата → свободное время → врач |
| Редактирование | Перенос предстоящей записи; форма заполнена текущими значениями |
| Удаление | Подтверждение; удаляются завершённые/отменённые записи согласно КР1 |
| Связанные данные | ComboBox врачей, справочник специалистов, ФИО пациента в записи |
| Поиск | ФИО врача, специальность, ФИО пациента; без учёта регистра |
| Фильтры | Статус и диапазон дат приёма; применяются совместно с поиском |
| Сортировка | Заголовки столбцов, в том числе время приёма и создания; даты сравниваются как LocalDateTime |
| Статистика | Всего, четыре статуса, активные, перенесённые записи, число переносов; администратору также пользователи |
| Экспорт | FileChooser, CSV/XLSX, только текущие строки в порядке таблицы |
| Пользователи | Администратор: создание пациента, изменение ФИО, удаление с подтверждением и проверкой связей |
| Валидация | Сервисы КР1: длины, уникальность логина, время, рабочие дни, 90 дней, конфликты расписания, права |
| Ошибки | Alert; форма и введённые значения сохраняются; отдельный текст неверного диапазона |
| FXML / CSS | Четыре FXML-файла и `hospital.css` |
| JDBC | Существующие Repository/DAO и DatabaseManager; SQL отсутствует в контроллерах |
| Отзывчивость | `FxWork` выполняет JDBC/экспорт в Task вне JavaFX Application Thread |

При создании запись относится к текущему пользователю. При переносе администратором исходный пациент сохраняется. Изменение статуса определяется временем приёма или явной отменой, произвольный статус через форму не задаётся. Обновление актуализирует статусы. Статистика показывает все доступные пользователю записи, независимо от фильтров таблицы. При существующем файле экспорта нужно выбрать новое имя: данные не перезаписываются.

## Проверки

```bash
# Бизнес-логика, PostgreSQL и экспорт; UI-тест пропущен без графического флага.
env -u TEST_DB_URL -u TEST_DB_USER -u TEST_DB_PASSWORD ./mvnw clean test
# Настоящие FXML-окна + PostgreSQL; нужен рабочий стол:
env -u TEST_DB_URL -u TEST_DB_USER -u TEST_DB_PASSWORD ./mvnw -Dhospital.uiTests=true test
```

Тесты используют изолированные контейнеры PostgreSQL. `JavaFxWorkflowTest` загружает каждый FXML, входит пациентом, создаёт запись через ComboBox/DatePicker, применяет фильтры, переносит, отменяет и удаляет запись через подтверждение; проверяет статистику и окно пользователей администратора. Существующие интеграционные тесты проверяют права, конфликты и конкурентную запись, ограничения дат, экспорт CSV/XLSX и сохранение данных. Файловый диалог операционной системы при автоматическом сценарии не открывается; экспортёры проверяются интеграционными тестами.

## Учебный архив

`student-hub-suite-rebuilt/` — предоставленный пример, не часть исходников Hospital и не входит в коммит. Он остаётся на диске целиком вместе с Android-клиентом. В данном архиве `.env` расположен в `backend/`, а не в корне, как указано в тексте задания.

В его Compose ошибочно опубликован внутренний порт PostgreSQL `5433`. Дополнение `scripts/demo-compose.override.yml` исправляет его на `5432` и выделяет отдельные внешние порты: БД `55433`, веб `18080`. Требуется современный Docker Compose с поддержкой `!override`.

```bash
docker compose --project-name hospital-kr2-example \
  --env-file student-hub-suite-rebuilt/backend/.env \
  -f student-hub-suite-rebuilt/backend/docker-compose.yml \
  -f scripts/demo-compose.override.yml up -d --wait db backend
curl http://localhost:18080/actuator/health
curl -I http://localhost:18080/
./mvnw -f student-hub-suite-rebuilt/javafx-client/pom.xml \
  -Dstudenthub.api=http://127.0.0.1:18080/api javafx:run
```

Остановка без удаления данных:

```bash
docker compose --project-name hospital-kr2-example \
  --env-file student-hub-suite-rebuilt/backend/.env \
  -f student-hub-suite-rebuilt/backend/docker-compose.yml \
  -f scripts/demo-compose.override.yml down
```

## Сценарий защиты

1. Показать Docker, health учебного backend и запуск его JavaFX-клиента.
2. Запустить Hospital. Войти пациентом; показать его записи и справочник врачей.
3. Создать запись, выбрав связанные объекты из списков; повторить на занятый слот и показать отказ.
4. Выбрать выходной/прошедшую дату: ошибка оставляет форму открытой. Закрыть её без сохранения.
5. Перенести предстоящую запись; проверить обновление таблицы и счётчика переносов.
6. Отменить запись; удалить её после подтверждения. Отказаться от подтверждения и показать, что строка остаётся.
7. Совместить поиск, статус и даты; отсортировать по приёму и созданию; экспортировать текущий список.
8. Открыть статистику, затем войти администратором и показать CRUD пользователей и ограничения удаления.
9. Показать слои: FXML → Controller → Service → Repository → PostgreSQL.

`Stage` — окно, `Scene` — его содержимое, `Node` — элемент дерева интерфейса. `FXMLLoader` создаёт дерево и контроллер; `fx:id` связывает элемент с полем `@FXML`, `onAction` — с обработчиком. `ObservableList` уведомляет таблицу об изменениях; `FilteredList` и `SortedList` предоставляют представления того же списка. `Task` выполняет работу в фоне, а его обработчики результата изменяют UI в потоке JavaFX. Ограничения расписания и прав повторно проверяются сервисом, даже если кнопка недоступна в интерфейсе.
