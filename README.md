# Java Hospital — КР3. Веб-регистратура клиники

Веб-приложение для сотрудников клиники. Регистратор записывает пациента к врачу, ведёт карточку приёма и работает с расписанием. Backend на Java 21 и Spring Boot раздаёт веб-интерфейс и предоставляет REST API для мобильного клиента следующей контрольной работы.

## Запуск

Понадобятся Docker с Compose и OpenSSL. Выполняйте команды из корня репозитория. Java и Maven для запуска в Docker устанавливать отдельно не требуется.

1. **Настройте подключение к PostgreSQL.** Если вы уже запускали КР1 или КР2, используйте тот же каталог проекта и прежний `.env` с действующим паролем базы. При первом запуске создайте файл и задайте в нём свой `DB_PASSWORD`.

   ```sh
   cp -n .env.example .env
   ```

2. **Создайте учётные данные веб-администратора.** Выполните один раз. Скрипт запишет email, временный пароль и ключ подписи JWT в локальный `.env.kr3`.

   ```sh
   sh scripts/init-web-env.sh
   ```

3. **Запустите PostgreSQL и веб-приложение.** Compose дождётся готовности обоих сервисов. При старте Flyway применит миграции.

   ```sh
   docker compose --env-file .env --env-file .env.kr3 -f docker-compose.yml -f compose.web.yml up -d --build --wait
   ```

4. **Войдите в регистратуру.** Откройте [localhost:8080](http://localhost:8080/). При первом входе используйте `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` из `.env.kr3`, затем задайте постоянный пароль. При следующих входах используйте его.

Проверить доступность сервера можно через [health](http://localhost:8080/actuator/health). После входа администратору доступен [Swagger UI](http://localhost:8080/swagger-ui.html).

Для остановки с сохранением базы в томе `hospital_data` выполните

```sh
docker compose --env-file .env --env-file .env.kr3 -f docker-compose.yml -f compose.web.yml down
```

## Что перешло из КР1 и КР2

- **Общая база.** Консольный клиент КР1, настольный JavaFX-клиент КР2 и веб-регистратура используют одну PostgreSQL с пациентами, врачами и записями. При миграции существующий приём сохраняет числовой ID для прежних клиентов и получает UUID для REST API.
- **Пациенты и сотрудники.** В карточке приёма указывается логин пациента, зарегистрированного через CLI или JavaFX. Сотрудник входит в веб-приложение по email. Если база пустая, для первой записи зарегистрируйте пациента в JavaFX или загрузите демоданные по командам ниже.
- **Расписание.** Запись доступна на ближайшие 90 дней. Приёмы начинаются по будням с 09:00 до 16:30 по Москве, каждые 30 минут. Пациент и врач могут участвовать только в одном приёме на одно время.
- **Статусы.** «Предстоит», «В процессе», «Завершена», «Отменена». Перенос меняет дату или врача и увеличивает счётчик переносов. Отмена освобождает время. Архивирование скрывает карточку из основной выборки сотрудников и сохраняет бронирование.

Для демонстрации на пустой базе после запуска Compose можно загрузить пациентов и примеры приёмов. Для этого шага нужен JDK 21. Команды рассчитаны на macOS/Linux и файл `.env` в формате `.env.example`.

```sh
set -a
. ./.env
set +a
./mvnw package -DskipTests
java -jar target/java-hospital-1.0.0.jar --seed
```

После загрузки укажите, например, `patient1` в поле «Логин пациента» при создании записи.

## Возможности КР3

| Роль | Доступ |
| --- | --- |
| Наблюдатель | Список и карточки приёмов, поиск, фильтры, сортировка, справочник врачей и аналитика |
| Регистратор | Дополнительно создаёт и редактирует записи, ведёт заметки и теги, архивирует и восстанавливает карточки, выполняет массовые операции, импортирует и экспортирует CSV |
| Администратор | Дополнительно управляет врачами и сотрудниками, просматривает аудит и Swagger |

Код КР3 находится в [backend](backend/). Для запуска его тестов с JDK 21 выполните `./mvnw -f backend/pom.xml test`. Пошаговый пример записи пациента, проверки CSV и работы с архивом приведён в [сценарии защиты](docs/kr3.md#сценарий-защиты).
